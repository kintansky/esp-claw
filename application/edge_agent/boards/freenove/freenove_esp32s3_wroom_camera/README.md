# Freenove ESP32-S3-WROOM-1 Camera Board

## Hardware Overview

| Feature       | Specification                                       |
|---------------|-----------------------------------------------------|
| Module        | ESP32-S3-WROOM-1-N16R8 (16 MB flash + 8 MB OPI PSRAM) |
| Flash         | 16 MB QIO @ 80 MHz |
| PSRAM         | Octal 80 MHz (wired to the OPI peripheral, no GPIO) |
| Camera        | OV5640 over DVP 8-bit (XCLK 20 MHz, SCCB on GPIO4/5 @ 10 kHz) |
| Storage       | On-board microSD slot, **1-bit SDIO** (CMD/CLK/D0 only) |
| LED           | On-board WS2812 on GPIO48, driven by RMT0           |
| Microphone    | None (this board has no on-board mic)               |
| Console       | **UART0 on GPIO43/44** via the on-board USB-UART bridge (CH340/CP2102) |

> This board does not include a microphone. Audio input / WebRTC / wake-word
> features that depend on `audio_adc` will be unavailable.

## GPIO Mapping

| Function                  | GPIO  | Notes                                  |
|---------------------------|-------|----------------------------------------|
| I2C SDA (camera SCCB)     | 4     | CAM_SIOD                               |
| I2C SCL (camera SCCB)     | 5     | CAM_SIOC                               |
| Camera XCLK               | 15    | 20 MHz, generated by LEDC              |
| Camera PCLK               | 13    |                                        |
| Camera VSYNC              | 6     |                                        |
| Camera HREF/DE            | 7     |                                        |
| Camera D0..D7 (Y2..Y9)     | 11, 9, 8, 10, 12, 18, 17, 16 |                |
| SDIO CMD                  | 38    |                                        |
| SDIO CLK                  | 39    |                                        |
| SDIO D0 (DATA)            | 40    |                                        |
| WS2812 LED data           | 48    | RMT0 channel 0                         |
| USB D+/D-                 | 19/20 | Internal USB PHY (USB-C)              |
| JTAG_EN (jumper)          | 3     | Strapping pin, left open               |
| UART0 TX/RX               | 43/44 | Available; not used as console        |

The following pins are reserved and not wired out for user IO:

- GPIO0, GPIO45, GPIO46 — strapping pins (boot mode, VDD_SPI, ROM messages)
- GPIO35, GPIO36, GPIO37 — internally bonded to the OPI PSRAM chip
- GPIO19, GPIO20 — internal USB PHY

## Important Notes

### Console must be UART0 (not USB Serial/JTAG)

The board exposes **two** USB ports:

- **USB-UART** (CH340/CP2102 bridge to GPIO43 = U0TXD, GPIO44 = U0RXD).
  This is what `idf.py flash` and the serial monitor use by default.
- **USB-OTG** (ESP32-S3 native USB on GPIO19/20). Useful for power or
  device mode, but **not** for the console on this board.

The adaptation sets `CONFIG_ESP_CONSOLE_UART=y` so app logs come out of
the USB-UART bridge on GPIO43/44. **Do not** set
`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y` — app logs would then go to the
OTG port and you would see the bootloader lines, then nothing, even
though the app is running normally. (This presents as a "stuck at
`call_start_cpu0`" symptom; the app is fine, the logs are just on the
other USB port. It can easily be misdiagnosed as a flash-mode problem
when the real fix is to change the console to UART.)

The flash command therefore targets the USB-UART bridge:
`idf.py -p /dev/ttyUSB0 flash monitor` on Linux (not `/dev/ttyACM0`).

### Camera SCCB needs the internal pull-ups + 10 kHz clock

The Freenove board does **not** fit external pull-up resistors on the
camera's SCCB lines (GPIO4/5). Without help, the ESP32-S3's default
internal pull-ups (~45 kΩ) are too weak to drive the SCCB bus at the
typical 100 kHz clock, and the OV5640 init fails with:

```
E sccb_i2c: s_sccb_i2c_transmit_receive_reg_a16v8: fated to transmit receive
E ov5640: ov5640_get_sensor_id: read pid_h failed
E esp_video_init: Failed to detect camera sensor with address=3c
```

The fix lives in two files:

- `board_peripherals.yaml` enables the internal pull-ups:
  ```yaml
  - name: i2c_master
    type: i2c
    role: master
    config:
      port: 0
      pins:
        sda: 4
        scl: 5
      sda_pullup_en: true
      scl_pullup_en: true
  ```
- `board_devices.yaml` drops the SCCB clock to 10 kHz so the RC rise
  time is short enough relative to the bus period:
  ```yaml
  - name: camera
    ...
    peripherals:
      - name: i2c_master
        frequency: 10000
  ```

50 kHz and 100 kHz were both tested and fail. 10 kHz works reliably.
Init takes ~50 ms (the OV5640 needs ~50 register writes during probe +
init), which is acceptable for an edge-agent workload.

**For better performance**, solder two 4.7 kΩ pull-ups from GPIO4 and
GPIO5 to 3V3, then set `sda_pullup_en` / `scl_pullup_en` back to
`false` and the SCCB clock back to 100 kHz. With external pull-ups
the camera init drops to ~5 ms.

### SD card is 1-bit SDIO, not SPI

The Freenove schematic only brings out **CMD / CLK / D0** (GPIO38/39/40) to
the microSD slot — there is no CS line and no D1/D2/D3. This is 1-bit SDIO
mode (`bus_width: 1`). The ESP-IDF SDMMC driver supports this, but throughput
is roughly half of 4-bit mode. If you need faster storage, use a different
board or wire the missing SDIO lines yourself.

### OV5640 vs OV2640

OV5640 is a 5 MP sensor, so the default format is 1024x768 (XGA) JPEG at
30 FPS, which is a good balance between image quality and the bandwidth
needed by the agent's vision pipeline. The `esp_video` driver exposes larger
resolutions (up to 2592x1944) when the application opens the camera with
explicit `opts.width / opts.height`; see `components/lua_modules/lua_module_camera/README.md`.

To verify that the OV5640 itself is healthy, the adaptation can be
temporarily switched to `CONFIG_CAMERA_OV2640=y`; the OV2640 responds
to SCCB at the same address 0x3C and is a useful "is the camera alive"
sanity check, even though its D0..D7 order does not match the
Freenove FPC pinout (so the captured image will be garbled).

### No microphone

`audio_adc` is intentionally not declared. Any feature that calls
`board_manager.get_audio_codec_input_params(...)` will fail with a NULL
handle. If you want to add a microphone, wire an I2S PDM mic (e.g., an
SPH0645) to free GPIOs and add the `audio_adc` device in
`board_devices.yaml`.

### WS2812 single-pixel "status" LED

The `led_strip` device is declared with `max_leds: 1` and `init_skip: true`,
so the Lua `led_strip` module can drive the on-board WS2812. The default
Lua bindings will only show one strip. Drive it like any other addressable
LED:

```lua
local strip = require("led_strip")
strip.init({ led_count = 1, gpio = 48 })
strip.set_pixel(1, 30, 0, 0)   -- dim red
strip.draw()
```

(The Lua `led_strip` module's exact API may differ; see
`components/lua_modules/lua_module_led_strip/README.md`.)

### Strapping pins

GPIO0, GPIO3, GPIO45 and GPIO46 are ESP32-S3 strapping pins. Do **not**
externally pull them at boot or the chip will enter download / low-power
modes. This board does not use them in the adaptation, so leaving them
floating (as the schematic does) is correct.

## Build & Flash

```bash
cd application/edge_agent

# Generate board-manager glue. Always rerun this after editing the YAML
# files under this directory, otherwise the stale generated C code under
# components/gen_bmgr_codes/ is compiled instead.
idf.py bmgr -c ./boards -b freenove_esp32s3_wroom_camera

# Build and flash. The Freenove board has two USB ports; the one you
# use for `idf.py flash` and `idf.py monitor` is the USB-UART bridge
# (CH340/CP2102 on /dev/ttyUSB0 on Linux, COMx on Windows), NOT the
# USB-OTG port.
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor    # Windows: COM3 / COM4 depending on bridge
```

If flash hangs at "Connecting...", hold **BOOT**, tap **RESET**, release
**BOOT**, then retry.
